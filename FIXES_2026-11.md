### F2 — A score save can never hang or vanish (M16 · SF-07 · B1)

**Problem.** `submitScore()` awaited the upsert with no deadline (supabase-js has none), so on
weak Wi-Fi a judge could sit on "Saving…" forever — and the one-submit-at-a-time guard
(`scoreSavingRef`) was released in exactly one place at the end, so every later Submit was dead
too. Worse, the draft was deleted *before* the score was written to the offline queue: if that
`localStorage.setItem` threw (storage full / blocked), the score was in neither place and the
guard stayed stuck. The offline flush had the same missing deadline, and a hung flush held
`flushingRef` forever, so no later sync could run.

**Change** (`src/ScienceFairJudging.jsx`):
- Module helpers after `writeDraft()`: `QUEUE_KEY`, `readQueue()` (never throws; corrupt → `[]`),
  `writeQueue(q)` (returns false instead of throwing), `SAVE_TIMEOUT_MS = 15000`,
  `withTimeout(promise, ms)` (resolves `{ error: { code: "TIMEOUT" } }` at the deadline, and turns
  a rejection into `{ error: { code: "FETCH_FAILED" } }`).
- `submitScore()` is now the guard + `saveScoreNow().catch(…).finally(release)` — `.finally()`,
  not try/finally (rule 37). `saveScoreNow()` holds the old body, with: a missing project handled
  ("removed by the organiser"); `withTimeout(upsertScore(payload), SAVE_TIMEOUT_MS)`; the queue
  written through `writeQueue()` and, if that fails, the judge stays on the form with
  `scoreErr` ("Your score was NOT saved …"), the draft kept, IT log `SCORE_NOT_SAVED`; the draft
  deleted and the score shown in the list only AFTER it is saved or queued.
- `SCORE_QUEUED.reason` is now `offline | timeout | server_error`.
- `runOfflineFlush()` uses `withTimeout()` per item and the queue helpers.
- New state `scoreErr`, shown under the Submit button (`role="alert"`), cleared by `startScoring()`.

**Docs:** `ADMIN_HELP` (+1 answer, `ADMIN_HELP_UPDATED` → 2026-11-04a), JudgeInstructions Step 6
(points 7–8), AdminInstructions "Scores stuck on a device".

**Tests:** new `scripts/e2e/save-robust.e2e.mjs` (11 checks). Mock gained `store.hangWrites`
(+ `store.releaseHangs()`) and `store.delayWrites`; the `failWrites` outcome is now decided when
the request arrives. **Before the fix 7 of the checks failed** (stuck on Saving…, nothing queued,
draft deleted with the score nowhere, Submit dead). After: 11/11, lifecycle 50, judging 36,
rubrics-2627 27, feedback 17. Lint 28/5. Build ✅.

**If something goes wrong:** a judge stuck on "Saving…" > 15 s means `withTimeout` is not on that
path. A score in neither the server nor `sf_offline_queue` → look for `SCORE_NOT_SAVED` /
`SCORE_SUBMIT_ERROR` in IT Logs (payload has judgeId, projectId, error). A slow-but-successful
save (> 15 s) is queued AND lands — the queued copy re-sends the same values, harmless.

**Commit:** `7f9d2b3`

### F3 — The offline queue: per-revision, self-retrying, never silently wiped (M17 · M18 · M19 · N9 · SF-06 · D2–D5 · B5)

**Problems.**
1. *D3* — `runOfflineFlush()` acknowledged items by judge+project. A re-score of the same project
   queued while the flush was uploading the older copy was deleted unsent.
2. *D4* — a flush could upload an older queued copy AFTER a newer direct save of the same score
   (last write wins on the server).
3. *D2* — the only automatic retry was the browser's `online` event; a score queued because the
   server failed (or a captive portal) waited for Sync Now.
4. *D5* — refused items were retried silently; the judge was never told.
5. *N9 / B5* — when the signed-in judge was missing from the judges list (Reset, Remove judge,
   or a stale empty list from the 8 s load timeout racing the response) the device deleted the
   ENTIRE `sf_offline_queue` — every judge's and school's entries — and every draft, with no log.

**Change** (`src/ScienceFairJudging.jsx`):
- Module: `newRev()`, `queueRev(item)` (older items without `rev` get `key@ts`), a direct-save
  counter (`nextDirectSaveSeq()` / `lastDirectSaveSeq()` — a counter, not `Date.now()`, rule 37),
  `QUEUE_RETRY_MS = 20000`, `UNSENT_KEY = "sf_unsent_scores"`, `keepUnsentScores()`, `dropDraftsOf()`.
- Queued items carry `rev`; failed ones also `attempts` + `lastError`.
- `runOfflineFlush()`: skips an item whose revision is no longer in the queue (superseded); after
  uploading, if a direct save of the same score finished meanwhile (`directSavesRef`, seq newer than
  at the start), re-sends the newer payload; removes exactly the accepted revisions.
  `OFFLINE_SYNC_FAILED` is logged on an item's 1st failure and every 15th (≈5 min), not every 20 s.
- New effect: while `offlineQueue.length > 0`, flush every 20 s and on `visibilitychange` → visible.
- `endRemovedJudgeSession(judgeId, sid)` (declared above the SESSION SYNC effect — declaring it
  below added a react-hooks/immutability finding): re-checks the judge row directly and ends the
  session only if that lookup succeeds and finds nothing; moves this judge's queued items to
  `sf_unsent_scores`, logs `UNSENT_SCORES_KEPT` (project ids + criteria numbers, no comment text),
  drops only this judge's drafts, shows `unsentNote` on the landing page.
- Judge sync banner: plain wording ("not sent yet … keeps trying on its own"), plus "the server
  has not accepted … tell the coordinator" once an item has failed twice.

**Docs:** `ADMIN_HELP` (lost internet; wrong number → Remove), `ADMIN_HELP_UPDATED` 2026-11-04b,
JudgeInstructions Step 6 point 3, AdminInstructions "remove a judge" answer.

**Tests:** `save-robust.e2e.mjs` +8 checks (19 total). Mock: a failing write now answers at once,
only successful writes are delayed by `delayWrites`. **All 8 new checks fail against the F2-only
code** (verified by stashing the source file). lifecycle 50, judging 36, alerts 19. Lint 28/5.

**If something goes wrong:** a score missing on the server but shown as scored → look in the
judge's `sf_offline_queue` (each item has `rev`, `attempts`, `lastError`) and `sf_unsent_scores`;
IT Logs `UNSENT_SCORES_KEPT` lists what a removed judge's tablet still held. A flood of
`OFFLINE_SYNC_FAILED` means the throttle (`attempts === 1 || attempts % 15 === 0`) is bypassed.

### F4 — Starting without the server: no false "School Not Found", never the wrong form (M20 · M21 · SF-08 · SF-09 · B2)

**Problems.**
1. B2 / SF-08 — `resolveSchool()` treated ANY failed lookup as "no such school". A judge whose
   tablet restarted with no connection saw **School Not Found** for the whole session, and nothing
   about the school (projects, rubric, schedule) was kept on the device.
2. SF-09 — when the rubrics read failed, `rubrics` stayed `[]` and `rubricFor()` fell through to
   `DEFAULT_RUBRIC`: the judge got the 10-criterion 42-point form. Ratings saved on it use criterion
   ids the department rubric does not have, so the project totals 0. (CLAUDE.md documents the
   DEFAULT fallback as intended for an EMPTY rubric row; a failed read is a different case.)

**Change** (`src/ScienceFairJudging.jsx`):
- Module: `CACHE_PREFIX = "sf_cache_"`, `cacheSet` / `cacheGet`, `publicProjectRow()` (drops the
  legacy name columns), `cachedRead(name, res)`: saves a successful read; on a failure that is NOT
  an unrun migration (MISSING_TABLE / MISSING_COL pass through untouched) returns the saved copy.
- Cached per school (`sf_cache_<sid>_<table>`): departments, categories, app_settings,
  judge_schedule, projects (public columns only), rubrics. Plus `sf_cache_school_<slug>`.
  Only anon-readable data. Judges, scores and every admin-only table are NOT cached (scores
  already had sf_scores_cache + the queue overlay).
- `resolveSchool()`: PGRST116 (zero rows) = not found; any other error → the device copy; no copy →
  `schoolUnreachable` → new "Can't reach the server" screen (data-testid `school-unreachable`) that
  reloads itself on `online` and every 20 s.
- `rubricsReady` state, set only by a successful (or cached) rubrics read. The scoring view shows
  "The scoring form could not be loaded — Try again" (data-testid `rubric-unavailable`) instead of
  falling back; `saveScoreNow()` refuses to save a scored project while it is false.
- Wording (U8): the scoring screen's "pending local save(s) not yet in backend" → plain words.

**Docs:** ADMIN_HELP (+1 answer, ADMIN_HELP_UPDATED → 2026-11-04c); JudgeInstructions Step 6
points 9–10; AdminInstructions Troubleshooting → new scenario.

**Test fixed on the way:** `project-codes.e2e` "judges see the new format after it is saved" read
the FIRST code that appeared after a reload. The project list and the settings load in parallel,
so the default format can show for a moment before the saved one — a pre-existing race that F4's
cache writes made frequent (failed 3 runs in a row). It now waits for the saved format; it still
fails if the format is never applied. 3/3 passes after.

**Tests:** new `scripts/e2e/offline-start.e2e.mjs` (11 checks). "Unreachable" = `store.failReads` on
every table: the dev server has no service worker, so a real offline reload cannot load the page.
**Against the pre-F4 code 9 of 11 fail.** Lint 28/5.

**If something goes wrong:** a tablet showing an OLD project list or form is running on its copy
(the server read failed; LOAD_FAILED appears in IT Logs once it reconnects). Clearing site data
removes the copies (`sf_cache_*` keys). "Can't reach the server" on a connected tablet = the
schools lookup errors with something other than PGRST116 — check the browser console.

### F5 — Screens catch up after a dropped connection (M22 · SF-21 · D1)

**Problem.** Supabase Realtime does not replay changes missed while a channel was down. When a
tablet slept or lost Wi-Fi and reconnected, the subscribe callback just went back to "live" and
nothing was reloaded: the admin's leaderboard, Alerts and Awards (Confirm all!) could run on stale
scores, and a judge's tablet could miss Lock Judging, a schedule change or a new assignment until
someone refreshed the page.

**Change** (`src/ScienceFairJudging.jsx`, the mount effect):
- `refreshAfterGap(sid)` reloads settings, projects, judges, scores, validations, deliberation
  notes, final decisions, departments, categories, rubrics, roster, panels, schedule, share link,
  activity log, IT log. At most once per 10 s — and a call inside the window is DELAYED to its
  end (`refreshTimer`), never dropped.
- Called when the channel reports SUBSCRIBED after having been live before (`everLive`) — the
  first join is not a reconnect (`rtDownAt` starts at setup, and init() has just loaded
  everything) — and when the screen becomes visible after more than 60 s hidden.
- `refreshTimer` cleared in the effect cleanup.

**First attempt failed its own test:** counting every SUBSCRIBED with `rtDownAt > 0` as a
reconnect made the FIRST join trigger a refresh, and a plain "skip if refreshed < 10 s ago"
throttle then swallowed the real refresh after an early drop. Fixed with `everLive` + the delayed
(trailing) refresh; the test now drops the connection twice, the second time inside the window.

**Docs:** ADMIN_HELP "Live updates seem frozen" (ADMIN_HELP_UPDATED → 2026-11-04d);
AdminInstructions `REALTIME_DOWN` line.

**Tests:** new `scripts/e2e/realtime-reconnect.e2e.mjs` (6 checks). It fakes the realtime server
with `page.routeWebSocket`: joins are accepted by echoing the client's `postgres_changes` bindings
back with ids (supabase-js rejects a join reply that does not match), sockets can be dropped on
demand, and joins are counted. Scenario: judge tablet live → drop → organiser locks judging →
rejoin → the lock must appear with no refresh; then drop again at once → organiser unlocks →
it must disappear. **Pre-F5 code: the "shows the lock it missed" check fails.** Lint 28/5.

**If something goes wrong:** a screen that does not catch up after a reconnect → check the
browser console for the channel status; `REALTIME_RECONNECTED` in IT Logs means the rejoin was
seen. Heavy admin screens reload the IT log (≤ 1,000 rows) on each catch-up — expected.

### F7b — The Validation award dropdown saves before anything changes (N1)

**Problem.** The award dropdown in Validation → Deliberation wrote straight into `finalDecisions`
(local state) on change, before any save; and the Save button was disabled for "Pending", so a
saved award could not be taken back. Scenario: admin saves A = 1st, switches A to Pending (Save
greys out), saves B = 1st. The admin's screen showed only B; the database held A = 1st AND
B = 1st, so every public viewer — and the admin after a reload — saw two 🥇. The Awards tab's
Clear / Re-confirm read the same wrong local state and skipped A.

**Change:** new state `awardDrafts` ({ pid: award }). The dropdown edits the draft only; the row
computes `savedAward`, `awardDraft`, `awardDirty`. Save is enabled whenever the draft differs from
what is saved — including "Pending" ("Save (remove award)"), which `saveFinalDecision()` already
wrote correctly (finalized = false). The draft is cleared only when the save succeeds
(`saveFinalDecision()` now returns true / false). An amber "Not saved yet — press Save" note shows
while a draft is pending. The min-to-place warning follows the draft.

**Docs:** ADMIN_HELP "Can I change awards after I finalize?" (+ how to take an award back),
ADMIN_HELP_UPDATED 2026-11-04f; AdminInstructions awards paragraph.

**Tests:** awards-integrity +5 (11 total): saving a place, "Not saved yet" with nothing written,
Pending saved → finalized false, the dropdown then shows the saved value, an unsaved change
writes nothing. **The 2 core checks fail on the pre-F7b code.** awards 28. Lint 28/5.

**If something goes wrong:** a dropdown that will not save → the button is only enabled when the
choice differs from what is saved; a red "NOT saved" = the write failed (DECISION_SAVE_FAILED).

### F7c — Ties stay visible until really decided; "ready" means every review is in (M27 · M28 · SF-05 · SF-13 · I5 · I6 · N7)

**Problems.**
1. SF-13 — `groupStatus()` / `tieGroups()` treated ANY confirmed place as deciding the whole
   group. 90 / 80 / 80 with only 1st saved read "Decided by hand", the tie alert switched off, and
   `groupPlaces()` returned only the confirmed map, so the podium showed 1st and nothing else.
2. N7 — confirmed A/B/C, then a re-score made C level with D for 3rd: still "Decided by hand".
3. M27 / SF-05 / I5 — a group was "ready" for Confirm all once each project had ONE review
   (`avg !== null`); with 3 scheduled visits per project, places could be locked in on 1 of 3.
4. I6 — `scores.submitted_at` only defaulted on insert; re-scores kept the first time.

**Change** (`src/ScienceFairJudging.jsx`):
- `groupTies(g)`: every medal-deciding tie (not only the first). `lastScoreAt(projs)`: latest score
  time (keys matched with `endsWith`, rule 60). `tieDecided(t, projs)`: every tied project has a
  saved award with `finalizedAt >= lastScoreAt`. `groupTie(g)` now = the first UNDECIDED tie, so
  `tieGroups()` / `hasTie()` / the alert keep a group until its tie is really decided.
- `groupStatus()`: states `tie` (undecided medal tie, even with places confirmed) · `open` ·
  `decided` (ties all decided) · `confirmed` · `partial` (some places confirmed, in line with the
  scores) · `changed`. New `missing` = projects with fewer reviews than `expectedReviews(p)`
  (scheduled visits, else the judges whose list holds the project). `clean` needs no `missing`.
- `groupPlaces()`: confirmed places win; places nobody confirmed go to the next projects with no
  saved award, in ranking order (share-ties rubric: their computed shared places).
- Awards tab: chips "Only some places confirmed" and "N still waiting for reviews"; Confirm on a
  partial group reads "✓ Confirm the remaining places".
- Score payload sends `submitted_at` (module `isoNow()` — no Date inside App, rule 37).

**Design note:** the existing awards test decides a 1st/2nd tie by saving those two places by hand
and leaves 3rd unconfirmed — that must still read "Decided by hand". So "decided" is judged per
tie (every tied project has a fresh saved award), not "every place confirmed".

**Docs:** ADMIN_HELP labels / ties / Confirm-all answers (ADMIN_HELP_UPDATED 2026-11-04g);
AdminInstructions awards steps, label table, "what the public sees", tie alert.

**Tests:** awards-integrity +8 (19 total), save-robust +1 (submitted_at). **Against the F7b code
all 8 award checks and the submitted_at check fail.** awards 28, prek-sped 16, min-place 21,
judging 36, lifecycle 50 all unchanged. Lint 28/5.

**If something goes wrong:** a group stuck on "Tie for Nth" after you decided it → one of the tied
projects has no saved award, or a judge re-scored after you saved (compare the award's saved time
with the latest score). A group never "ready" → `expectedReviews()`: count its schedule visits /
the judges listing the project vs the Reviews column.

### F7d — No Finalize over an undecided tie; confirmed places cannot be regrouped or moved (N3 · N6) + F7c rule refined

**Problems.**
1. N3 — `finalizeBlocker()` checked admin approval, closed deliberation and open concerns, but not
   ties. A tie that decides a place could be finalized and published; the podium then ordered the
   tied projects by creation date (import order) with nothing to show it was a tie.
2. N6 — confirmed places are keyed by project, not award group. Switching a department from

**Change** (`src/ScienceFairJudging.jsx`):
- `finalizeBlocker()`: refuses while `tieGroups()` is not empty, naming each group and place
  ("A tie still decides a place in Middle School (2nd Place)…"). Checked by the button AND
  `finalizeResults()` (rule 18 — the handler already calls finalizeBlocker()).
- `updateDeptAwardGrouping()`: refused after Finalize, and while the department has any confirmed
  1st–3rd ("Clear them on the Awards tab first").
- `updateProject()`: refused when a project holding a confirmed place would change award group
  (new department, or new category in a per-category department). Other edits are untouched.

**F7c rule refined (found by `judging.e2e`):** F7c counted a tie as decided only when EVERY tied
project had a fresh saved award. `judging.e2e` breaks an Alpha/Beta tie for 1st by saving only

new Finalize gate the stricter rule blocked that event flow. `tieDecided()` now needs all but ONE
of the tied projects to have an award saved after the last score change. SF-13 (only the untied
1st saved) and N7 (a stale decision) are still caught — their awards-integrity checks still pass.

check and stopped at 19 with the strict rule — the reason for the refinement), awards 28,
prek-sped 16, min-place 21, lifecycle 50, proj-edit 6, import 24. Lint 28/5.

**If something goes wrong:** Finalize greyed out with "A tie still decides a place" → open
Deliberation and save an award for the tied projects (all but one). "Places for …" will not change
→ that department has confirmed places: Awards tab → Clear confirmed places first.
